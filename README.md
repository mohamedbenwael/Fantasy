# المزاريطة فانتازي — نسخة لايف متصلة بـ FPL الرسمي

## اتغيّر إيه؟
- الموقع بقى بيسحب **كل لاعبي البريميرليج الحقيقيين** (الأسماء، الأندية، الأسعار، النقط،
  نسبة الملكية، المباريات) مباشرة من الـ API الرسمي لفانتازي البريميرليج — تلقائيًا،
  من غير أي إدخال يدوي منك.
- لوحة الأدمن بقت بس شاشة حالة اتصال + زرار "مزامنة الآن" (مفيش تعديل أسعار يدوي
  خالص دلوقتي، لأن البيانات كلها حقيقية ولايف).
- أول ما أي حد يدخل الموقع لأول مرة، بيتبني له فريق افتراضي (15 لاعب حقيقي) جوه
  ميزانية £100 مليون، وبعدين يقدر يعدّل من تبويب الانتقالات زي ما اتعود.

## ليه محتاج ملف `api/fpl.js`؟
الـ API الرسمي بتاع FPL (`fantasy.premierleague.com/api`) **مقفول بسياسة CORS** —
يعني مينفعش الموقع يناديه مباشرة من جافاسكريبت شغال في المتصفح. الملف `api/fpl.js`
ده "بروكسي" بسيط شغال كـ Serverless Function على Vercel: بيستقبل الطلب من موقعك،
بيوديه لـ FPL، وبيرجّع الرد لموقعك. من غيره الموقع مش هيقدر يجيب أي بيانات حقيقية.

## البنية
```
mazareta/
├── api/
│   └── fpl.js          ← البروكسي (Serverless Function)
├── public/
│   └── index.html      ← التطبيق نفسه (نفس الملف اللي بعتهولي، بعد التعديل)
└── vercel.json
```

## النشر على Vercel (الطريقة اللي عندك)
1. اعمل مستودع جديد على GitHub وارفع فيه المجلد ده بالكامل (`api/` و `public/`
   و `vercel.json`).
2. من [vercel.com](https://vercel.com) → **Add New Project** → اختار المستودع.
3. Vercel هيكتشف الإعدادات تلقائيًا من `vercel.json`. مفيش أي environment
   variables أو إعدادات إضافية مطلوبة — كل حاجة شغالة out of the box.
4. اضغط **Deploy**. بعد كذا ثانية هيديك رابط زي
   `https://your-project.vercel.app` — افتحه وهتلاقي الموقع شغال لايف.
5. أي مرة تعدّل في `public/index.html` وترفعها على GitHub، Vercel هينشر النسخة
   الجديدة تلقائيًا.

### لو محتاج تتأكد إن البروكسي شغال لوحده
افتح في المتصفح: `https://your-project.vercel.app/api/fpl?type=bootstrap`
المفروض يطلعلك JSON كبير فيه بيانات كل لاعبي البريميرليج.

## لو مستضاف على Netlify بدل Vercel
نفس الفكرة بالظبط لكن لازم تنقل `api/fpl.js` لمجلد `netlify/functions/fpl.js`
وتغيّر `module.exports = async function handler(req, res)` لصيغة Netlify Functions
(`exports.handler = async (event) => {...}` وترجع `{statusCode, body}` بدل
`res.status().json()`). قولّي لو عايزني أجهزلك النسخة دي كمان.

## ملحوظة عن GitHub Pages
GitHub Pages بيستضيف ملفات ثابتة بس (HTML/CSS/JS) ومفهوش سيرفرات — يعني
مش هيقدر يشغّل `api/fpl.js`. لو مصمم تستخدمه، هتحتاج تستضيف البروكسي في مكان
تاني (زي Vercel أو Cloudflare Workers مجانًا) وتوجّه `FPL_ENDPOINT` في
`index.html` لرابطه.

## أداء وتحديث البيانات
- البروكسي نفسه بيعمل cache على مستوى الـ CDN لمدة دقيقة لدقيقتين (حسب النوع)
  عشان معدلش نضغط على سيرفر FPL كتير.
- الموقع كمان بيخزن نسخة في shared storage لمدة 5 دقايق، فكل الزوار بيستفيدوا
  من نفس النسخة المخزنة بدل ما كل واحد يعمل طلب لوحده.
- زرار "مزامنة الآن" في لوحة الأدمن بيتخطى الكاش ده وبيجيب أحدث نسخة فورًا.
- لو الاتصال بـ FPL فشل تمامًا (مشكلة نت مؤقتة مثلاً)، الموقع بيرجع لآخر نسخة
  متخزنة عنده، ولو معهوش حاجة خالص بيشتغل بنسخة احتياطية صغيرة بس عشان
  الموقع ميقعش.
